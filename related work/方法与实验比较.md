**1. AVerImaTeC：动态证据历史已有直接前例**

原始入口：[论文](https://arxiv.org/abs/2505.17978)。原文：[PDF](01-图文事实核验/01-AVerImaTeC/原文.pdf)，版本 2505.17978v2。

任务是用网页证据核验真实图文主张。论文有 1,297 个主张；每个主张附问题—答案证据、来源、标签和说明。标签包括支持、反驳、证据不足、冲突/选择性呈现。它区分文字错误与图片误用，并采用独立标注者进行证据充分性复核（§3–5，pp.3–6）。

**最接近我们的部分是 §7.1（pp.7–8）**：系统维护不断更新的 evidence history；动态问题生成依赖已取得的证据，再调用反向图搜、文本搜索、图片搜索或 VQA。并行、动态、混合提问均有比较。所以不能把已有工作概括成“只做静态核验”，也不能把“随新信息继续推理”单独当创新。

评价要求结论和证据同时合格。其所谓 conditional accuracy 是证据分数未达阈值时将该题计错，**不是只在证据过关子集上计算准确率**（§6，p.6）。人工参考证据之外的合理证据可能被低估；LLM 评判也不是无误真值。主实验对照还包括给定 gold evidence 和关闭检索（§7.3，p.9），用于分离检索和后续判断困难。

需要特别注意标签比例：Table 2 的 train/dev/test 反驳比例分别为 95.3%/92.8%/78.1%。不能直接拿总体准确率解释模型能力。文中约 5% 主张用核验文章日期代替未知的原始日期；搜索/网页时间也只是近似（§8，p.10）。公开旧数据不能自动满足模型知识截止日期之后的新事件要求。

**评价设计启示**：固定当前证据，先隔离修订维护；主试验目标平衡支持/反驳，并报告逐类表现；引入证据支撑审计与人工视觉事实对照。拟研究差异缩小为“已使用证据被撤回后，既有候选状态与淘汰依据如何影响恢复”。这只是候选差异，不是新颖性证明。

**2. VERITE：真假类别平衡不等于模态平衡**

原始入口：[论文](https://arxiv.org/abs/2304.14133)。原文：[PDF](01-图文事实核验/02-VERITE/原文.pdf)，版本 2304.14133v3。

论文区分 True、Out-of-Context（OOC）与 MisCaptioned（MC）。其构造中真实图片可与正确/错误图注配对，同一真实图注也可与匹配/错配图片配对（§3.1–3.2，pp.4–7）。因此，仅靠识别图片或图注本身不应稳定获得标签。正文分别演示图像侧和文字侧捷径；不是只比较某一个强多模态模型与一个弱文本模型。

其检测器使用 CLIP 特征和小型 Transformer（§3.4，p.8），所以文中的分数不能直接推断当前大模型表现。论文报告真实集、构造集及模态消融；还指出将 VERITE 拆成二分类子任务可能破坏其模态平衡，作者不推荐把这种拆法当作原基准使用（§5，p.13）。

CHASMA 生成的图文错配也并不全是有效负例：人工审查的 100 项中有意外正确和无法判定的样本（p.8）。**随机换图不能自动得到“假”的标签。**小样本核查比例也不能无条件推广到所有构造数据。

**评价设计启示**：同一图文模型做去图对照；另外预先制作四个经人工核验的视觉关系变化对照，只改变必要图像关系且重新标注，检查结论是否随视觉事实变化。题目、图注、文件名和“据说/辟谣”等词不得泄露标签。同源图像与改写按事件分组。我们使用新的动态协议，不把二分类改造称为官方 VERITE 成绩。

**3. EvoDiverse：多样性维护和双种群已是强近邻**

原始入口：[论文](https://arxiv.org/abs/2606.10587)。原文：[PDF](03-假设生成与维护/06-EvoDiverse/原文.pdf)。PDF 首页标注 ICML 2026；此处引用 arXiv 版本，不据首页标注推定 PMLR 卷页。

论文将假设搜索看作有限验证预算下的高质量、多样候选产生。LLM 提出后代，外部目标函数 h(x) 给分。冷/热种群使用不同选择压力，交换概率使用近似平行回火的形式：

`A = min(1, exp[-ξ(β_cold−β_hot)(h(x_hot)−h(x_cold))])`。

ξ 按观察到的交换率调节。论文明确这是近似过程，LLM 提案诱导的分布并不是已知固定平稳分布；能量尺度会影响交换（§3、§6，pp.3–5、9）。因此不能把输出分数套入 softmax 就宣布得到校准后的贝叶斯后验。

实验覆盖分子、方程与算法发现；比较普通 EA、独立种群、高温探索及种群迁移，按各任务给定的 oracle 验证预算评估。附录 B.1.1 和 Table 4 明确多种群共享总 oracle 预算（p.16）。这一预算并不自动等于我们实际 GPU 时间、图像编码与生成 token 的总成本。

附录还比较无 MH 门控的随机交换及能量变换（pp.29–30）。这里的“多样性”使用各任务的分子结构或程序表示；不能直接把自然语言措辞差异替代事件解释差异。主体 Table 1 也不是每个指标都最优，例如 GSK3β 的 Top-10 Avg 上 Ensemble 更高；不应写成全面统治所有指标。

**评价设计启示**：普通多假设池允许新生候选；若要宣称恢复机制有效，后续必须比较普通多样性维护和随机档案回放。我们推理时没有外部真值 oracle，假设排序只能依赖当前可见证据，真实标签只用于评测。仅换领域或增加一个档案都不足以证明新意。

**4. HypoGeniC：它的奖励来自带标签数据**

原始入口：[论文](https://aclanthology.org/2024.nlp4science-1.10/)。原文：[PDF](03-假设生成与维护/05-HypoGeniC/原文.pdf)。

输入是带标签样本 `(x, y)`。每个假设作为一个候选规则，奖励由已测试样本的正确率加 UCB 探索项构成：`r_i = accuracy_i + α sqrt(log(t)/n_i)`。错误样本积累到阈值后生成新假设，再按奖励更新假设库（§2.1，p.3）。这并非对每条情报都不知道真假的在线调查。

推理策略包括最佳单假设、筛选后加权投票、一步/两步自适应选择。附录 B.2 的假设去重使用在带标签样本上的预测正确性向量，而不只看句子 embedding（pp.15–16）。这给我们“用可检验后果区分假设”提供依据，但它仍依赖监督，不能原样移植到未知真伪证据。

主体 Table 1 报的是跨若干设置的最佳结果，正文也说明部分提升受基线拒答影响（pp.5–6）。论文并不证明每种设置都优于 few-shot，且 oracle inference 是事后从候选中挑最好，不能作为实际可部署方法。对我们尤其有用的是分开分析“生成了可用假设”和“是否选择/应用正确”。

§7（p.9）讨论了无显著准确率提升的设置、预训练暴露和多轮调用延迟。论文提出的定性新见解也不是本项目可直接复用的事实规则。

**评价设计启示**：记录合理假设从未生成、生成后淘汰、仍在池中但排序/应用错误三种失败；不把候选存在率当最终准确率。禁止使用目标标签、标注证据答案或事后裁决给在线种群打分。所有附加判断调用计费。

**5. CONFACT：来源处理必须成为对照，不能只比朴素多数票**

原始入口：[DOI](https://doi.org/10.24963/ijcai.2025/1073)。原文：[PDF](02-冲突证据与来源依赖/03-CONFACT/原文.pdf)。出版信息为 IJCAI 2025。

任务是从可信度不同、立场冲突的文本材料回答事实问题。ModC 有 611 条模型识别冲突样本，HumC 有 287 条人工确认冲突样本（§3、Table 1，p.3）；**不能把 611 写成人工确认集**。论文给出固定检索材料以保证可重复，并报告准确率和 Macro-F1。

方法在检索、排序、生成三处引入来源背景。它比较直接回答、多数票、显式辨别、CoT，以及来源背景拼接、过滤、打分、集成等策略（§4，pp.4–5）。多数票在不平衡情形下可能看似准确却有较低 Macro-F1；更复杂的来源方法也不总更好。

结果中，单个可信度分数用于排序/过滤可能损害效果：来源可信度与内容相关性不同，过滤还可能丢掉解释冲突所需材料（pp.6–7）。来源背景应作为有出处、可能不完整的证据，不能作为绝对真值。所读主体不能证明作者给出的全部机理解释已经被因果实验确认。

**评价设计启示**：所有方法看到相同来源信息；D 不能独享真值来源图。方法比较需加入来源信息相同的重启和仅去重基线。明确撤回状态只隔离维护问题，自行识别可靠性需另设条件。来源机构名、同图传播和内容事实分别建模。


方法检验需要进一步与经典依赖维护、信念修订、序贯推断和动态图核查进行同条件比较。这里的局部文献分析不构成新颖性证明，受控条件见[实验协议](../experiments/01-图文证据修订先导/experiment-protocol.md)。
