# 多领域情报数据集设计

公共事件、市场与行业、案件调查具有不同的证据形式和判定标准。本设计定义三个领域的候选任务与共享协议，不表示相应正式数据集已经构建。[公开资源目录](../datasets/README.md)提供选材入口。

正式自建集统一遵循[数据集设计约束](自建数据集设计约束.md)：**目标事件发生在所选模型已核实的知识截止日期之后；每例真假混合且案例间比例不同；证据随真实时间逐步公开；图文信息共同参与判断；覆盖典型 hard cases，并保留附录案例与失败分析。**这些是准入条件，适用于下列每个领域。

## 为什么考虑多个领域

核心问题是：收到的图文材料不一定可靠，来源可能相互依赖；新证据和更正到来后，系统能否维护多个合理解释，撤回失效依据，必要时恢复先前被排除的候选，并给出有证据支持的结论。

公共事件、公司经营和案件调查都有这种需求，但它们的错误来源、可接受答案和证据标准不同。分别构建领域数据集，可以检验方法是否只适合新闻图文错配，还是能适应财务口径冲突、调查关系图错误等问题。三个领域可共享协议，保留各自任务与评分，不通过改实体名称凑出三个数据集。

“开源情报”是一种获取方式，市场和警务是应用领域；命名时可用“公共事件”“市场/行业”“案件调查”区分主题，分别注明材料是否来自公开来源。领域数量和规模本身不构成方法创新，仍需证明新的推理困难及现有方法的不足。

## 三个候选方向

| 方向 | 候选问题与图文材料 | 公开资源可提供什么 | 仍需我们构建什么 |
|---|---|---|---|
| 公共事件 / 开源情报 | 某张照片是否支持某时某地发生某事？同图不同图注、现场照片、新闻与原始发布记录相互核对 | AVerImaTeC、VERITE、MOCHEG 提供图文核验基础；GDELT 可筛选新事件，CrisisMMD 提供灾害素材 | 实际更正/补证链、图片出处、独立来源关系、每阶段可判定边界 |
| 市场 / 行业调研 | 截至某日，公司某业务增长的判断是否得到资料支持？核对财报页图、图表、公告与行业报道 | TAT-DQA、ChartQA 提供视觉文档/图表任务；FinQA、TAT-QA 提供数值对照；SEC EDGAR 是潜在披露来源 | 同一指标的期间、币种、口径和版本对齐；自然错误/重述记录；正确计算和可审计的结论依据 |
| 警务犯罪 / 案件调查 | 哪些事件经过与当前可见线索相容？某个关系或时间线是否有足够支撑？材料可含有明确来源的照片/视频帧、公开记录与关系描述 | VAST 提供调查场景与图数据；CAIL 提供案件文本；UCF-Crime 提供视觉事件素材；开放警务表与 ICIJ 提供背景/关系资源 | 合法可用且有判定依据的图文案情、逐阶段可见线索、排除/保留解释的依据；现有资源不能直接拼成真实完整案卷 |

市场方向优先考虑能落到文档和数字上的事实判断，区分“事实是否成立”和未来预测，避免用后来的股价涨跌裁定当时材料真假。警务方向优先评测可观察事件、证据一致性与证据不足，不把异常行为、报案或关系连接等同于对个人的有罪结论。

## 图文能力必须真正参与结论

每个领域的正式主集都要有实际图片及对应文字，且存在需要视觉信息才能核实的约束：公共事件中的图像同源/场景对应，市场中的图表轴、单位、页面布局，调查中的可见动作、物体与时序关系。

解析表格、人物关系图和文字截图不自动满足这一要求。关系图可作为建模结构；如果输入只是三元组，仍属于结构化/文本推理。表格转图片和视频抽帧可以用于受控实验，但要记录转换来源，并检查文字输入是否已经泄露全部视觉事实。没有自然视觉证据的样本留作辅助集。

## 共享记录格式，按领域保留标签

| 层次 | 拟记录字段或信息 | 作用 |
|---|---|---|
| 问题 | `case_id`、领域、固定目标命题、目标时刻、回答范围 | 防止把现实随时间变化误标成历史材料错误 |
| 证据 | `evidence_id`、原始内容/图片、模态、原始 URL、字节哈希、版本 | 保留可回查材料，区分原文和模型生成描述 |
| 时间 | 事件发生、材料发布、归档、实验可见时间 | 避免只凭发布时间假设拥有旧版网页 |
| 来源与修订 | 来源 ID、转载/共享观测依据、`supersedes`、撤回记录、关系是否已知 | 区分独立证据、重复转述和真正的更正 |
| 呈现 | 各阶段可见材料、可搜索范围、查询与返回日志 | 可重放模型当时实际获得的信息 |
| 评估私有信息 | 原子命题真假/未知、判断依据、阶段充分性、可接受解释、最终答案、审查记录 | 只供评估器使用，不泄露给候选排序或检索 |

一份文档可以同时含真、假、尚不可核实的命题，不能简单按整份来源分成可信/不可信。文字内容、图片真实性及图文对应也要分别标注。来源依赖未知时保留 unknown，不把模型猜测出来的图当作 gold。

现有[开发数据契约](../experiments/data/image-text-pilot/data-contract.md)可提供格式起点，但它对应四个受控案例，不是上述三个领域已经建好的统一数据集。

## 构建与搜索协议的候选设计

1. **先做可取得性和可判定性审查。** 从目录选少量材料，核实图片字节、来源许可、是否能只凭证据回答固定问题，再决定哪个领域先建。取得文档不等于取得完整题包。
2. **将自然历史与受控顺序分别标记。** 自然案例须保存可回查的版本及到达时间；对静态集人为加入错配、撤回或重排，应记录每次改造。两类可并行研究，不能混称为真实事件回放。
3. **执行事件时间门禁。** 固定 checkpoint 并登记有来源的知识截止日期，目标事件发生时间必须严格晚于该日期；共用多模型主集取截止日期最大值。日期未知或区间重叠者暂不进入主集，新闻发布日期不能替代事件发生时间。再按事件、原图、公司/报告或案情模板检查同源泄漏和后训练/检索污染。
4. **允许查材料，隔离终局答案。** 优先用冻结的证据库，在第 t 轮仅开放当时材料。核验裁决页、最终案情总结、之后的更正、搜索摘要中暴露的答案及评估字段都应在可见性层面隔离；简单在提示里写“不要搜索答案”不够。开放网页搜索留作独立设置，并保留所有返回内容与泄漏审查记录。
5. **保留不必改变判断的案例。** 新材料可能是重复、无关或错误更正。不能让所有后到信息都意味着应反转，也不能将“证据不足”强行标成真或假。
6. **核对答案再冻结划分。** 每阶段标出能知道什么、还不知道什么；审查依据优先于模型表现。模型答对与否不能决定样本是否进入测试集。正式数据按原事件/材料组划分，变体和多轮不能算作独立事件扩充规模。
7. **保持比例与到达轨迹差异。** 主集每例都有真实和错误命题，按低/中/高占比及不同时间轨迹分层；累计曝光、当轮新增、当前有效材料分别统计，未知单列，同源重复另计。自然数据不为凑比例伪造消息；最终真值与比例不进入在线推理。
8. **登记难例和失败。** 覆盖虚假多数、关键反证迟到、伪更正、图文错配、来源独立性修订、初始解释遗漏和证据不足；依[附录规范](案例与失败分析规范.md)记录各方法的候选/依据变化及失败原因，不只展示成功案例。

## 方法与评测如何共用

后续可比较：每轮基于现有材料重新推理、单结论记忆、多候选维护、带依赖撤回的经典维护方法，以及 GNN/时序 GNN 和假设进化方法。GNN 应使用与其他方法相同的可见证据和建图信息；人工真值图单列 oracle，对建图错误与图上推理错误分别分析。进化方法的“适应度”不能偷用隐藏裁决。

共同指标可以包括最终结论与依据正确性、每阶段的过度断言/证据不足判断、错误依据被纠正后的恢复情况、无关更新下的稳定性、置信度校准及总计算/检索成本。财务数值题增加数值与单位准确率，调查题增加关系/时间线证据覆盖；不能用一个总分掩盖领域差异。

图文主结果还需去图、仅图、可用时的文字视觉事实对照，并把视觉识别失败与假设维护失败分开。统计按独立事件/公司报告/案情分组；受控与自然案例分别报告。各领域的指标、样本量和计算预算应在测试前确定，并保留独立的领域统计。
