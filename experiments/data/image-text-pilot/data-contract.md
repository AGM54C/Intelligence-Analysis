# 图文案例、证据和评估数据契约

D001–D004 为合成场景样例，包含实际 PNG、阶段安排、构造标签和视觉关系变体。日期为虚构场景内时间，标签未经独立人工复核。代码接口见[使用说明](../../../evidence-pilot/README.md)。

**每个案例需要分开的文件**

| 文件 | 内容 | 模型能否读取 |
|---|---|---|
| `cases/<id>/public/question.json` | 固定问题、目标时刻、中性 ID | 是 |
| `cases/<id>/public/evidence.jsonl` | 材料原文、来源、版本、图片引用和当时可见元数据 | 只能读取当前阶段允许的记录 |
| `cases/<id>/assets/*.png` 或 jpg | 实际图片、原图或经记录的变换 | 只能读取当前阶段允许的图片 |
| `cases/<id>/schedule.json` | 两条历史每轮选取哪些记录，以及修订状态 | 编排器读取，不整份放入提示 |
| `cases/<id>/private/gold.json` | 目标标签、逐阶段证据充分性、可接受解释、支持链、错误依据 | 仅评估器 |
| `cases/<id>/private/visual_facts.json` | 人工可见事实记录 | 仅人工视觉事实对照，不进入主试验 |
| `cases/<id>/audit.json` | 取材、许可/引用、时间核查、标签审查、排除记录 | 研究者/评估器 |

四个合成样例遵循上述结构。程序以字段白名单构建请求，不能将整个案例目录或 manifest 文本交给模型。文件名去掉 fake/true/refuted 等提示词；供模型展示的 URL 若含核验结论，应提取有出处的中性材料，不丢弃核查记录。

**证据记录的最小字段**

`evidence_id, modality, text, image_ids, source_id, source_url, published_at, archived_at, arrival_stage, version, supersedes, observation_root_id_if_known, provenance_basis`。

发布时间、实际事件发生时间和实验呈现阶段分别记录。来源根节点未知就置空；不能由模型猜测后自动视为真值。同图转发与文字内容的独立采访关系分别标注。图像记录包括字节哈希、尺寸、原图出处、裁剪区域及父图 ID。

**三阶段设计**

- 第 1 阶段：两条历史共有的不完整证据，允许多种解释。
- 第 2 阶段：一条增加误导材料，另一条增加不误导的匹配材料；内容长度、图片数量和格式尽量匹配，并记录无法匹配的差异。
- 第 3 阶段：相同的有效材料 E* 和相同修订状态，移除过时材料。更正只通知材料状态，图文归属仍需根据实际图片与出处推断。

例如，环境可以说“E02 已撤回”，但不直接说“目标图片就是某年的旧图，答案为反驳”。后者可能把目标推理答案一起给出。若任务需要比对档案图，模型必须真的看到可比较的图片。

证据充分性先由人工审计，不能以“9B 做对”为纳入标准。最终要提供足以支持/反驳的证据；如果只能证明图片没法佐证某事件，问题也应限定为图片的佐证关系，不能把“无法证明发生”标成“证明没有发生”。

**标签、分组与视觉检查**

正式数据以独立事件为单位；多个图注、裁剪或改写若源自同一事件，使用同一 event_group 并按组统计。绝不把两条历史和不同阶段当成新增事件数。

每例标注：文字单独能确定什么、图片单独能确定什么、跨模态结合新增哪条有效约束。图片只作装饰的案例不承担视觉推理论证。标签平衡本身不能保证消除单模态捷径。

视觉关系对照，要求保留问题和文字元数据，在合法图像替换后目标标签确实改变；人工核对后才可运行。无合法变体则记缺失，不用随机换图生成伪负例。

**冻结清单**

来源可访问、图片字节齐全、标签与支持链可核对、模式/提示/模型版本已记录、开发与诊断按事件分开、E* 哈希相同、私有字段不可见、没有静默截断，全部满足后才把诊断案例标为 FROZEN。DEV_READY 只表示合成数据可用于程序验证，不代表正式冻结或独立人工标注。

**评测记录与失败归类**

每次请求保存模型/处理器/框架版本、完整输入哈希、图片哈希、可见证据 ID、继承状态、seed、开始/结束时间、原始输出、最终解析结果、输入/输出/视觉 token、是否截断、峰值显存与 GPU 用时。若框架不提供某一用量字段，用 null 并说明，不估成实测。

人工核查最终标签与支撑链；尽可能隐藏方法名和历史条件后审查。候选以实际事实内容和可检验后果对齐，不能只按 ID 或词面相似性判断存活。若只有单人复核，明确这一限制；不声称双人标注一致性。

“生成过合理候选”检查当前阶段所有 `hypotheses`；“候选仍在池中”只检查 `selected_ids` 指向的候选。把已生成但已淘汰的条目算进存活池，会掩盖本实验希望测量的状态变化。

先区分视觉识别、图文对应、证据本来不足、来源依赖、从未生成合理候选、候选被淘汰、排序/应用错误、错误采纳后到消息和格式/截断故障。多个原因可同时出现，不强行归为单一机理。

`case_manifest.csv` 的 `reference_label` 记录构造参考标签，仅用于数据管理与评估，不能进入模型请求。清单只列出实际存在的案例。
