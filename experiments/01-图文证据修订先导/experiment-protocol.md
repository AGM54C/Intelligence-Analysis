# 图文证据修订的受控实验协议

## 研究问题

在最终有效证据相同的条件下，早期误导材料是否通过继承的解释影响最终结论？如果存在差异，错误来自视觉理解、证据不足、合理候选未生成、候选被淘汰，还是保留后选择错误？

该协议使用环境明确给出的撤回状态，以隔离证据修订后的状态维护。完整情报任务还要求模型判断新材料是否真实、是否适用于当前问题，两者应分别评价。

## 案例与阶段

固定目标问题及目标时刻，每个案例使用 `clean`、`misled` 两条历史：

1. 阶段 1：共享不完整材料，可保留多个解释。
2. 阶段 2：分别加入不误导和误导的材料，记录长度、模态及格式差异。
3. 阶段 3：提供相同的有效证据 E* 与相同修订状态，撤回过时材料。

E* 应由独立于模型输出的证据检查确定可判定范围。认定一张图无法证明某事件，不等于证明该事件没有发生。事件、来源、原图和衍生变体按组划分，不能将多个阶段当作独立样本。

仓库提供 D001–D004 四个合成图文样例，覆盖图片语境、裁剪上下文和来源依赖；标签由场景构造规则给定，未经独立人工复核，不属于正式真实事件基准。正式数据遵循[数据集设计约束](../../docs/自建数据集设计约束.md)。

## 方法

| 方法 | 继承状态 | 当前阶段的候选 |
|---|---|---|
| A：单解释更新 | 最多一个旧解释 | 重新判断并保留最多一个 |
| B：全量重启 | 无 | 比较最多四个解释，不传给后续阶段 |
| C：普通多假设维护 | 最多四个旧解释 | 新增最多四个，合并后保留最多四个 |

A/B/C 共用模型、当前有效证据、图片顺序、公共提示和生成配置。原始对话与 thinking 不继承。候选身份及事实表述不可在同一 ID 下改变；修订解释使用新 ID 并记录父候选。C 的淘汰项仅写入日志，不反馈给后续阶段。

B 的阶段 3 输入与配对种子应在两条历史之间完全相同；请求哈希与实际处理器张量用于检查这一条件。模型输出可有随机性，输入不一致则属于实现混淆，不能解释为历史效应。

## 对照

| 条件 | 设置 | 目的 |
|---|---|---|
| 去图 | B、阶段 3，保留相同文字并移除图像 | 检验视觉信息是否影响判断 |
| 人工视觉事实 | B、阶段 3，以不含目标裁决的可见事实替代图像 | 分离感知错误与推理错误，属于 oracle 诊断 |
| 后到错误报道 | 误导历史的阶段 4，保留既有有效反证并加入错误消息 | 检验是否盲从最新信息 |
| 视觉关系变体 | B、阶段 3，保留问题和文字，修改决定标签的视觉关系 | 检验判断是否响应真实的视觉变化 |

视觉关系变体需要重新核对标签与充分性，不能随机换图后沿用答案。人工视觉事实和明确撤回状态不等同于自动核查能力。

四例配置的核心条件为 4 × 2 × 3 × 3 = 72 次请求，对照为 4+4+12+4 次，总计 96 次。此计数表示调用结构，不是模型成绩或成本估算。

## 输出、失败与评价

最终回答为 `supported`、`refuted`、`insufficient`。保留所有非法输出、截断和系统异常，不能删除失败调用提高分数。非法输出不自动重试，后续阶段继承最近的有效状态。

分别统计结论正确、错误、证据不足与非法输出；同时报告逐类召回、作答覆盖率以及“标签正确且依据充分”的数量。引用 ID 存在并不能保证其支持结论。未知的依据正确性保留为空。

按独立事件成对比较 A、C 的 `Acc(clean)-Acc(misled)`，并列出正确→错误、错误→正确及拒答变化。B 提供不继承状态的参照。四个合成样例仅用于实现检查，不支持总体性能或统计显著性主张。

候选诊断区分“从未生成”“生成后淘汰”“仍保留但选错”。只在曾生成合理解释的轨迹中计算淘汰后恢复；恢复延迟从证据已足够的阶段开始，未恢复者单列。候选语义、依据和错误原因依[案例分析规范](../../docs/案例与失败分析规范.md)核查。

## 扩展机制的公平比较

候选恢复的设计见[证据修订与候选恢复](../../候选IDEA集合/03-图文证据修订与候选恢复.md)，不属于上述 A/B/C 的已实现能力。其检验应包括全量重启、普通候选池、来源去重加同容量档案、随机或相似度档案检索、经典 TMS/ATMS，以及使用相同图文输入的图核查方法。

档案只能保存当时实际生成的内容，不能由答案回填。依赖失效仅触发重评，不能直接认定被恢复候选正确。竞争者因虚假支持获得高分而造成的淘汰也需检查，不能只记录候选自身的反证。

区分固定修订后追加预算与固定全程总预算。模型加载、视觉编码、生成、评分、检索、档案重评和失败调用均计入成本；相同请求数不等于相同耗时。只有在同信息、同容量和可比较成本下仍存在收益，才能支持相应机制主张。

## 复现信息

保存代码、配置、模型快照、数据与图像哈希、实际输入、随机种子、原始输出、处理器版本、用量和失败状态。运行目录由程序创建，使用方式见[代码说明](../../evidence-pilot/README.md)。可复现的流程输出与实际模型性能需明确区分。
