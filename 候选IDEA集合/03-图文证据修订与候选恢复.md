# 图文证据修订与候选恢复

## 问题

一个解释可能因早期错误图文、重复报道或错误来源关系而被淘汰。后来更新证据后，即使活动候选的评分已经修正，已删除的解释也不会自动返回；重新生成又可能付出额外成本或再次遗漏。

要检验的是：**保存选择决策的证据依赖，并在依赖失效时针对性地重评候选，是否比全量重启、普通档案检索或经典依赖维护更有效。** 它是 [02 · 动态多假设进化](02-动态多假设进化.md) 中的选择与恢复机制，可以在固定检索和固定评分器条件下单独比较。

## 恢复对象是选择决策的依据

只保存“哪个候选被哪条反证打败”不完整。候选也可能因容量限制、竞争者得到虚假支持或多样性去重而未被保留。

例如 H1 与 H2 在有限池中竞争，错误材料只支持 H1，H2 因排序落后而被淘汰。撤回该材料时，H2 自身的支持/冲突集合没有变化，但 H1 的分数降低，先前淘汰 H2 的理由可能已经不成立。因此依赖应覆盖**被淘汰候选、当时的竞争候选和实际选择规则**。

| 保存对象 | 内容 |
|---|---|
| 候选内容 | 对象、目标时刻、解释、待验证前提及可区分预测 |
| 评分依据 | 支持/冲突项、来源组、权重、证据 ID 与版本、未验证前提成本 |
| 选择记录 | 保留/淘汰规则、竞争候选、容量、分数差或其他实际判定条件 |
| 来源假设 | 哪些分组、独立性或图文同源判断参与了评分 |
| 档案索引 | 材料/来源组/选择条件到受影响记录的反向索引 |

纯按分数取前 K 个候选时，可记录淘汰候选与边界候选的分差；有多样性约束时应保存实际选择条件，不能用单一分差冒充全部依据。这些记录描述算法为什么作出选择，不是现实事实正确性的证明。

## 修订与重新选择

1. 识别证据版本、来源分组、权重或适用范围的变化，保留原始历史。
2. 对受影响评分项撤去旧贡献、加入当前贡献；参考 02 的增量公式。
3. 查找受这些项影响的候选及竞争/淘汰记录，包括自身分数未变但比较条件变化的档案候选。
4. 按当前全部有效材料重新评估，再与活动候选一起选择；相关性检索或索引遗漏的档案也需有可记录的检索范围。
5. 对无法被现有候选解释的新约束，允许生成新候选。档案只能恢复过去存在的解释，不能保证真实解释曾被生成。

某条淘汰依据失效只表示需要复核，不表示候选已经正确或一定重新入池。其他未撤回反证仍然生效；来源重新分组也不自动判定内容真假。候选分数修订、档案召回、最终重新选择三步分别记录。

有限档案会遗漏解释，依赖抽取也会漏边或误连。恢复机制不能宣称精确逆转整段历史搜索，更不能保证开放世界中所有合理解释都被覆盖。

## 机制定位与 GNN 的关系

GNN 可帮助估计来源关系、证据与主张相容性；关系图和反向依赖索引也可以由规则、抽取器或人工受控输入建立。图上得分更新与历史候选是否重新进入比较，是可分开的实验对象。

主设置由系统从可见图文和更正材料判断依赖/状态，不附赠真假标签或完整来源图。明确告知撤回状态、人工视觉事实或真实关系图的设置用于隔离机制误差，单独报告。当前先导的显式撤回协议属于这种受控诊断，不能等同于完整自动情报分析。

[01 · 来源依赖与预算推理](01-来源依赖与预算推理.md) 的主动调查和条件性认证可作为额外方向。该机制不要求把主动检索、GNN、求解器和进化算子全部接入。

## 区分机制与简单组合的对照

| 比较 | 要回答的问题 |
|---|---|
| 全量当前证据重启 vs 保留档案 | 记忆是否有用，还是历史反而保留了偏差 |
| 同容量随机/相似度档案检索 vs 按选择依赖召回 | 收益来自更多记忆，还是来自定位受影响记录 |
| 只保存候选自身冲突 vs 保存竞争与选择条件 | 来源更正影响竞争者时，是否仍会漏掉可恢复候选 |
| 只重评活动候选 vs 同时重评相关档案 | 修订评分是否足以解决历史淘汰，还是需要改变候选可达性 |
| 经典 TMS/ATMS 或合适的记忆/重生机制 vs 本方案 | 开放式解释、软评分和不确定依赖是否形成额外问题；不能预设经典方法无法适配 |
| 相同账本与评分器的简单组合 vs 联动更新 | 是否存在超出来源去重、重采样与普通档案的机制收益 |

可设置“来源贡献修订开/关 × 依赖召回开/关”的因子对照，并固定其余输入、容量和预算；报告交互及失败条件，不仅报告最佳完整系统。动态环境进化、序贯多假设跟踪、依赖维护已有相关概念，新增差别需要原文核对与这些对照支持。

## 算法贡献的判别条件

核心命题是：在有限候选池中，证据修订不仅改变候选分数，还可能使历史选择依据失效；显式追踪这些依据能否提高恢复质量或降低重评成本，需要独立检验。

固定且已知的候选全集、精确评分和已知依赖构成一个受限设置。在此条件下，普通动态 top-K、增量重算或经典依赖维护可能已经足够；仅对这个设置重新命名，不能支持新的算法贡献。

开放候选生成、不确定依赖、来源组拆分合并和有限档案构成额外困难。需要分别说明这些因素使哪项既有假设不再成立，以及提出的规则具体解决了什么，不能只把更复杂的任务描述当作算法创新。

| 检验 | 支持或否定什么 |
|---|---|
| 相同账本、评分器和档案容量的普通组合基线 | 排除收益仅来自来源去重、更多记忆或额外评分 |
| 精确依赖与估计依赖分别评价 | 区分维护规则的作用与依赖识别误差 |
| 固定候选全集与开放候选生成分别评价 | 检查动态排序是否已解释全部收益，定位生成与恢复的额外作用 |
| 同时报告结论质量、证据质量、重评次数与总成本 | 排除以大量额外计算换取恢复率的解释 |
| 自然修订、伪更正和无关更新共同评价 | 检查恢复机制是否以错误复活或过度翻转为代价 |

可研究的理论目标包括：在明确假设下，定向重评与全量重评的选择结果是否一致；定位受影响候选需要多少工作；依赖漏检或档案淘汰会怎样破坏这种性质。这些是待证明的目标，不能外推为开放世界中必然找回正确解释。

若合理适配的经典方法或普通组合能够解释全部收益，应将贡献限定为数据、测量或系统应用。若存在额外收益，还需用上述分解说明收益来自哪条机制，并保留方法输给简单基线的条件。

## 案例与失败分析

正式案例须满足[新事件与逐步补证规范](../docs/自建数据集设计约束.md)。重点观察虚假多数、独立性后来被推翻、关键反证迟到、伪更正、初始解释遗漏及证据不足；按实际假信息比例和证据延迟分层。

至少区分看错图、来源分组错误、适应度错误、未生成正确解释、生成后被淘汰、召回遗漏、召回后仍选错和错误复活。恢复速度从材料已足够的阶段计，早期合理的不确定性不记为失败。具体附录结构见[案例与失败分析规范](../docs/案例与失败分析规范.md)。
